## なぜカルーセルなのか

LinkedInの投稿本文は3,000字上限、約200字で折り返される。長文の専門記事を本文で成立させる形式は存在しない。深い内容を保存・再訪される形で届ける唯一の手段が**ドキュメント投稿（PDFカルーセル）**であり、これはLinkedInで最も滞在時間が長い形式である。滞在時間は配信量の主要因のため、密度の高いカルーセルはリーチの面でも最有利になる。

投稿本文は「読ませる」ためではなく「PDFを開かせる」ために書く。結論を本文で言い切らない。

## 配信順序

```
Week 1   02 The Silent Quarter    共感の射程が最も広い。最初の母集団を作る
Week 3   03 The Trust Surface     監査ページで保存される。ECの接触面が開く
Week 5   01 The Japan Entry Sequence  最も networks を要求する。土台ができてから
```

カルーセルは2週間に1本を上限とする。間の週は運用仕様のテキスト投稿で埋める。ドキュメント投稿を連続させると、1本あたりの初速が割れて全体の配信量が落ちる。

## ビルド

```
node docs/knowledge/linkedin/render-carousel.mjs docs/knowledge/linkedin/carousel-NN-name.html
```

同ディレクトリにPDFを出力する。既存のPlaywrightを使用しており新規依存はない。プロジェクトのPlaywrightがブラウザ未取得の場合、`PLAYWRIGHT_CHROMIUM_PATH` で既存ビルドを指定できる。

## 新しいデッキを作る

`carousel-01-*.html` を複製して本文を差し替える。CSSは `deck.css` を全デッキで共有しており、デッキ側にスタイルを書かない。デッキごとにCSSを複製すると必ず見た目がずれる。

**必ず溢れ検査を行うこと。** `.slide` は `height:1350px` かつ `overflow:hidden` のため、溢れた内容は無言で切り落とされる。

```js
[...document.querySelectorAll("section.slide")]
  .map((s,i)=>({i:i+1,h:s.scrollHeight})).filter(x=>x.h>1350)
```

高さ調整用の `<div style="height:NNpx">` は flex 子要素であり、詰まった版面では既に潰れている。溢れが出た場合、これらを縮めても効果はない。表の行 padding（`table.tight`）か本文そのものを削る。

## デザイン規約

| 項目 | 値 | 理由 |
|---|---|---|
| ページ | 1080 × 1350（4:5） | モバイルフィードの占有面積が最大 |
| 1ページ目 | 大見出し ＋ 目次 ＋ ページ数 | ドキュメント投稿は1ページ目がサムネイル。縮小表示で読め、かつ範囲が伝わること |
| 地色 | `#FBFAF8` | LinkedIn UIは純白。わずかな紙色で「投稿」ではなく「資料」として視認される |
| 書体 | Outfit（見出し）／ Noto Sans（本文） | paradigmjp.com と同一。遷移時の同一ブランド認知 |
| 本文ウェイト | 400 | スマホ実寸は約380px幅。300は可読性が破綻する |
| アクセント | `#1D4ED8` 単色 | 装飾量と説得力は反比例する |
| 最終ページ | 問い ＋ オファー1行 ＋ URL | 価格は出さない |

写真・アイコン・グラデーション・多色は使用しない。

## 全デッキ共通の構成規律

- 中核主張を1つに絞り、全ページをその論証に従属させる
- 各ゲート／段階に「省略した場合の代償」を必ず添える
- **後半に「今はやめておけ」ページを必ず置く。** 買うなと言えることが権威の源泉であり、事例ゼロの状態で信頼を作る唯一の手段である
- 最終ページの問いは、相手が事実を1つ答えるだけで自らをICPだと明かす形にする。コメント欄がそのまま接触リストになる
