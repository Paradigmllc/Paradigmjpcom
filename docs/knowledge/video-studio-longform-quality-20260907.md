# 自作OSS動画スタジオ：長編品質の診断と改善順序

## コンセプト

所有者が再確認した目的は、HeyGen / Runway / Kling / Seedanceを個別契約することではない。ComfyUI、Vast.ai、HyperFramesと専門OSSを統合し、投稿可能なショートから長編まで自作・低コスト量産すること。SaaS名は品質の比較対象。OSSの登録数やMP4生成成功を完成条件にしない。

## 今回のコード実測

- `config/engine-profiles.yaml` は40件。承認5、pending25、blocked10。承認済みでもworkerの実稼働・映像品質の保証ではない。実測済みWan素材は前回の別記録を参照。
- `ClientBrief.duration_seconds` の上限は600秒。標準プランナーは45秒超を7区間で処理し、300秒では30/48/72/66/42/24/18秒になる。台本を展開せず汎用見出しを置くため、長編用のショット設計には不十分。
- 600秒を標準プランナーへ渡すと144秒・132秒の区間がShotの120秒上限を超え、実際にValidationError。入力上限600秒をもって10分制作対応とは表示できない。
- ComfyUI素材を `normalize_clip(loop_source=False)` で指定尺に揃える際、`tpad=stop_mode=clone` が末尾フレームを複製する。生成が短いままでも、後段の尺検査には合格し得る。FFmpegの既存機能の誤った使い方であり、新OSS追加では解決しない。
- `qa.py` は技術適合を検査するもので、物語、動き、視聴維持、人物一貫性などの創作品質を保証するものではない。

## 実装した限定修正

既存ComfyUIAdapterで、正規化前に動画ストリームの尺を検査する。音声やコンテナだけが長い場合も合格させない。出力FPSの1フレーム以内の丸め差のみ許し、それ以上の不足は日本語エラーにする。元素材は診断用に保存されるが、静止尺埋めした成果物をcompletedとして返さない。正当な静止画像の生成・編集は維持する。

成功した素材の元解像度・FPS・尺をEngineOutputのprovenanceに残し、最終MP4への拡大とネイティブ生成品質を区別する。既存モデル/ワークフロー承認は変更しない。独立した新DB/API/画面は追加せず、既存の実行結果契約を使う。

実物検査：前回の2.041667秒MP4は元尺で合格、5秒・30秒の指定では拒否。追加課金・再生成なし。これは品質の最低条件の修正であり、画質向上や長編完成の証拠ではない。GPU開始前の費用予測・尺適合preflightは未接続。

## 今回の進め方と次の設計案

1. 既存のPython/Pydantic、認証API、スタジオGUI、プロジェクト記録を利用する。章・台本・ショット・生成物・人の評価が同じIDで結び付く契約へ拡張する。単なる別ダッシュボードを増やさない。
2. 長編は「章 → ナレーション区間 → 複数ショット → 音声同期 → HyperFrames章マスター → 全体マスター」。秒数だけを増やさず、各ショットに内容・視覚意図・人物/商品参照・利用素材・権利・編集イン/アウト点を持たせる。
3. まず30〜60秒の本編品質区間を実制作し、音声・図解・生成映像を混ぜて評価する。それを単純複製して長編にはしない。次に異なる章内容で3〜5分、さらに10分超の復旧可能な分割制作へ進む。
4. 専門経路は、生成映像、人物/口形、音声/字幕、3D/図解、修復/アップスケールに分離する。未承認OSSはサンドボックスで固定バージョン・モデル権利・VRAM・品質・コストを検証後に登録する。商用不適合モデルを無理に有効化しない。
5. GPUは同じモデルの仕事をまとめ、初回展開を繰り返す費用を抑える。保存・再開・二重実行防止・停止確認を実ジョブへ接続し、常駐GPUの無期限放置や無限リトライを避ける。
6. 完成基準は全編の人によるレビュー、聞ける音声、字幕同期、一貫性、破綻、採用可能な1分あたり費用、成功率、再開試験。今回のdry-runはこの品質証明に数えない。
